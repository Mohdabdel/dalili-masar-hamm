# Vertical Slice تجريبي داخل Dalili Lab

نموذج تحقق (Validation) لمسار كامل من الروتين إلى بطاقة المتعلم والتغذية الراجعة، بثلاثة أحداث مرجعية فقط: الإفطار، الغسيل/الملابس، التسوق. كل شيء تحت `/lab/*` وبيانات Lab المحلية فقط — بلا أي مساس بمسارات الإنتاج أو قاعدة البيانات أو ملفات CSV الأصلية.

## ملاحظة قبل البدء: الصور

الحزمة الخارجية (20 ملفاً) غير متاحة داخل بيئة العمل، ولن يُفترض محتواها ولن يُنشأ لها Mapping وهمي. تُستخدم فقط الصور الموجودة فعلاً في المشروع:

- 8 صور منزلية نهائية: ترتيب السرير، ترتيب الأغراض، إخراج النفايات، تعبئة الماء، تجهيز وجبة خفيفة، إخراج الأطباق من الغسالة، **طي الملابس**، **ترتيب الملابس بالخزانة**.
- 3 لقطات + لوحة مصدر لخزانة المؤن.
- صورتا خيارات الوجبة.

كل خطوة بلا صورة مطابقة تحصل على **Placeholder واضح باسم الخطوة**، ويُسجَّل ذلك في التقرير النهائي. Visual Mapping الكامل يجري لاحقاً بعد نجاح الـSlice.


## نموذج البيانات (داخل Lab فقط)

```text
LabParticipationSpec
  id, eventId, phase?, level (simple|moderate|advanced), context
  title_ar
  majorSteps: LabMajorStep[]

LabMajorStep
  id, order, instruction_family_ar, instruction_short_ar, visual_asset?
  substeps: LabSubstep[]

LabSubstep
  id, order, instruction_family_ar, instruction_short_ar, visual_asset?
  executionOptions?: LabExecutionOption[]   // طرق تنفيذ بديلة متساوية للخطوة نفسها

LabExecutionOption
  id, label_ar, visual_asset?
```

`visual_asset` = مسار صورة موجودة فعلاً أو `null` (يعرض Placeholder باسم الخطوة). Mapping الصور في ملف واحد: `step_id → asset`.

`executionOptions` ليست خطوات متتابعة ولا مستويات: هي بدائل متكافئة لتنفيذ الخطوة ذاتها، تُعرض بلا ترتيب أفضلية، وتختار الأسرة منها واحدة (أو تتركها مفتوحة) داخل Workspace، فتظهر داخل إطار الخطوة نفسه في البطاقة بلا إضافة إطار جديد.

اختيار الأسرة في Workspace يُحفظ **مرتباً صراحةً**:

```text
LabThisTimeSelection
  specId
  selected: { stepId, order }[]      // ترتيب تنفيذ صريح، لا Set ولا ترتيب ضمني
  chosenExecutionOptionByStepId: Record<stepId, optionId>
  supportTools: string[]
```

Snapshot بطاقة المتعلم — نسخة مجمدة وقت الاعتماد، لا تُعاد توليدها من الـFixture:

```text
LabCardSnapshot
  id, participationSpecId, version, createdAt      // مرجع المصدر للرجوع والتعديل لاحقاً
  title_ar                                          // منسوخ وقت الاعتماد
  frames: LabCardFrame[]                            // مجمدة
  supportTools: string[]                            // أدوات مستقلة، لا تدخل البطاقة

LabCardFrame
  sourceStepId
  order
  text_short_ar        // نص منسوخ، لا مرجع
  assetRef | null      // مسار منسوخ، لا مرجع
  executionOptionLabel_ar?   // إن اختارت الأسرة طريقة تنفيذ
```

الإطار الختامي «انتهينا» جزء من `frames` المجمدة. تغيّر أي Fixture لاحقاً لا يغيّر بطاقة معتمدة سابقاً؛ التعديل ينتج Snapshot جديداً بنسخة أعلى مع بقاء السابق كما هو.

لا حقول تقييم ولا نسب ولا مؤشرات إتقان في أي من النماذج.


## المسار المنفذ

```text
/lab/start → /lab/routine → اختيار الحدث
        → المرحلة (عند وجودها) → مستوى المشاركة (مرة واحدة)
        → قائمة المشاركات المناسبة → مساحة عمل الأسرة
        → معاينة → اعتماد → بطاقة المتعلم → التنفيذ → تغذية راجعة → دورة الحياة
```

- المستوى يُسأل مرة واحدة عند مستوى المرحلة، ويُخزَّن في حالة Lab، ولا يُعاد سؤاله داخل أي مشاركة.
- مساحة عمل الأسرة تعرض الخطوات الرئيسية مع Accordion لفتح الخطوات الأصغر، وتسأل: «ما الذي تريدون أن تشمله المشاركة هذه المرة؟» ثم «أين تنتهي هذه المرة؟» — اختيار حر لخطوة كاملة أو جزء منها أو عدة خطوات.
- «ما الذي قد يساعد؟» يبقى أدوات مستقلة (جدول بصري، الآن/بعد، مؤقت، لوحة اختيارات، أخبره مسبقاً، قائمة مصورة، Visual Builder) قابلة للفتح في شاشة أخرى أو الطباعة، وغير إلزامية لإصدار البطاقة.
- بطاقة المتعلم: صورة + 2–3 كلمات لكل خطوة + «انتهينا». لا شروح، لا إعدادات، لا أسباب.
- التنفيذ: خطوة واحدة في الشاشة (صورة، نص قصير، التالي)، والأدوات الداعمة عند الطلب فقط.
- التغذية الراجعة: مريحة / عادية / صعبة اليوم (أسباب اختيارية عند الأخيرة فقط).
- دورة الحياة: نكررها / نغيّر شيئاً / نوسّع / نجعلها من روتيننا / ليس الآن — والتوسعة تعيد إلى Workspace بلا اختيار تلقائي.

## المحتوى المرجعي (Fixtures)

**الإفطار → قبل الإفطار → بسيط**: تحضير الطاولة، إحضار مكونات الوصفة، وضع الطعام على المائدة، إبلاغ الأسرة بأن الإفطار جاهز.
«تحضير الطاولة» بثلاث خطوات رئيسية: فرش المنضدة (أحضر/ضع/افرد المفرش)، تحضير أدوات الطعام بعدد المشاركين (حدد العدد/الأطباق/الملاعق والشوك)، وضع الأدوات على المائدة (الأطباق/الملاعق والشوك/الأكواب).
«إبلاغ الأسرة» بثلاث خطوات: حدد الشخص، اذهب إليه، أخبره — مع دعم اختياري: قائمة مصورة بأفراد الأسرة وبطاقة «الإفطار جاهز»، وطرق التعبير الثلاث معروضة كخيارات متساوية.

**الغسيل/الملابس** بلا فرض قبل/أثناء/بعد: جمع الملابس، فرز الملابس، وضعها في الغسالة، إخراجها/نقلها، طي الملابس، إعادتها إلى أماكنها — وهنا تُستخدم صور الملابس المتاحة فعلياً.

**التسوق** (منزل → مجتمع): مراجعة القائمة، العثور على غرض مألوف، وضع الأغراض في العربة، المشاركة عند الدفع، إدخال المشتريات بعد العودة.

الصياغة تُعاد استخدامها من عناوين الفرص والأفعال والخطوات في مستودع المعرفة الحالي (قراءة فقط)، مع تحويل `make_it_easier` إلى دعم اختياري و`whats_next` إلى اقتراح توسعة اختياري. لا نقل لـ indicators أو mastery أو معايير نجاح أو لغة تدريبية/علاجية.

## الملفات

جديدة داخل Lab:
- `src/lab/data/slice/breakfast.ts`, `laundry.ts`, `shopping.ts` — الشجرة الهرمية والنصين القصير والأسري.
- `src/lab/data/slice/index.ts` — سجل موحّد ودوال بحث حسب الحدث/المرحلة/المستوى.
- `src/lab/data/slice/visual-map.ts` — `step_id → asset` مع تقرير الخطوات بلا صورة.
- `src/lab/components/StepTree.tsx` — Accordion هرمي متاح لوحة مفاتيح وقارئ شاشة.
- `src/lab/components/StepFrame.tsx` — إطار صورة/Placeholder موحّد.
- مسارات: `/lab/slice` (نقطة البداية)، `/lab/slice/$eventId/level`، `/lab/slice/$eventId/participations`، `/lab/slice/workspace/$specId`، `/lab/slice/preview/$specId`، `/lab/slice/card/$snapshotId`، `/lab/slice/run/$snapshotId`، `/lab/slice/feedback/$snapshotId`.

معدّلة (إضافة فقط):
- `src/lab/state/types.ts` و `lab-state.tsx` — أنواع Spec/Snapshot واختيارات هذه المرة (بلا كسر الحالة القائمة).
- `src/lab/components/LabShell.tsx` و `src/routes/lab.index.tsx` — رابط دخول الـSlice.

بلا أي تعديل على مسارات الإنتاج أو Supabase أو CSV الأصلية أو مكونات الإنتاج.

## التحقق قبل التسليم

اختبار E2E بالمتصفح للتدفقات الثلاثة، فحص RTL وأهداف اللمس والتنقل بلوحة المفاتيح وتسميات قارئ الشاشة، وفحص نصّي للتأكد من خلو الـSlice من لغة التقييم/الإتقان/النسب.

## التقرير النهائي

رابط البداية، التدفقات الثلاثة، الملفات، نموذجا البيانات، Mapping الصور، الصور غير المستخدمة، الخطوات ذات Placeholder، ما أُعيد استخدامه من المستودع، نتائج E2E وRTL/Accessibility، الشاشات التي تطيل المسار بلا قيمة، وتقييم وضوح خطوة اختيار المستوى قبل رؤية المشاركات.
